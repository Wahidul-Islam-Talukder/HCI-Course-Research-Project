Impact of a Gamified IDE on the Productivity of Programmers with ADHD
An academic Human-Computer Interaction (HCI) research proposal exploring how gamified features integrated into an Integrated Development Environment (IDE) could support the focus, motivation, workflow, and productivity of programmers with Attention Deficit Hyperactivity Disorder (ADHD).
Project overview
Programmers with ADHD may experience challenges such as task initiation difficulties, time-management demands, interruptions to concentration, and difficulty sustaining effort on repetitive tasks. This project proposes adding supportive gamification features directly to an IDE, rather than relying only on external coping strategies or workplace accommodations.

The proposal uses Werbach and Hunter’s 6D Gamification Framework to guide the design of an IDE plugin. Its central goal is to explore whether timely prompts, progress feedback, and optional rewards could help developers resume work, break larger tasks into manageable steps, and maintain motivation.
Research questions
1. What specific productivity challenges do programmers with ADHD face while using standard IDEs?
2. How can gamified elements within an IDE promote better motivation and focus for programmers?
Proposed plugin concept
The paper outlines three core features:
- Nudges: A prompt intended to help a developer return to a task after the IDE has been left idle in the background. The proposed prompt can show the code snippet the developer was previously working on.
- FocusPoints: Experience points (XP) intended to reward behaviours such as making small, manageable commits and starting tasks promptly.
- Unlock Goodies: An optional reward mechanism through which earned FocusPoints can be exchanged for IDE themes and icon packs.
The paper includes draft interface mock-ups of these concepts in its appendix.
Proposed research methodology
The proposal describes a mixed-methods study combining an online survey, semi-structured interviews, and IDE interaction telemetry.

The planned study includes:
1. Participant recruitment: Target professional software engineers who are formally diagnosed with or self-identify as having ADHD. The proposal suggests convenience and purposive sampling, with an initial target of approximately 20–25 participants for plugin testing and interviews, alongside a broader online survey.
2. Pre-deployment research: An online survey and a first semi-structured interview to understand participants’ development workflows, productivity challenges, executive-function demands, and current coping strategies.
3. Proposed plugin use: A four-week deployment period in which participants would use the gamified IDE plugin in their normal workflow.
4. Post-deployment research: A follow-up semi-structured interview exploring participants’ experiences with the features and their perceived effects on workflow, focus, and productivity.
5. Data analysis: Qualitative analysis of interview transcripts, alongside statistical analysis of survey responses and IDE telemetry. The proposal identifies measures such as time to first keystroke, commit frequency, and interactions with the plugin.
The proposal also describes anonymising collected data and avoiding the collection of proprietary source code or company data through the plugin telemetry.

Project status and scope
This document is a course-based research proposal. It presents the research motivation, research questions, literature review, proposed plugin features, study design, data-collection instruments, and draft interface mock-ups. The study and plugin deployment are presented as proposed work; this repository does not claim that the proposed experiment was conducted or that empirical findings were obtained.

Prepared as an academic project for the Research Methodology course at BRAC University.
